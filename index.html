2026-11-18 Hard

Typed Multi-Tenant Permission Engine with Role Inheritance & Audit Trail

You're building the authorization core for a SaaS platform where each tenant defines its own role hierarchy, roles inherit permissions from parent roles, and every access decision is recorded in a typed, immutable audit trail. The compiler must enforce every role shape, permission grant, inheritance chain, and audit event — no escape hatches allowed.

Goals

  • Define all branded primitives, the PermissionAction union, Role/Tenant interfaces, AccessResult discriminated union, and the three-variant AuditEvent discriminated union with no `any` usage.
  • Implement `resolvePermissions` to walk the role inheritance chain iteratively or recursively, emit a RoleInherited event per edge, guard against cycles, and return a ReadonlySet<PermissionAction>.
  • Implement `checkAccess` to look up a user's role, delegate to `resolvePermissions`, and return a typed AccessResult (granted or denied) while forwarding RoleInherited events.
  • Implement `buildAuditTrail` and `summariseAudit` so that all access requests produce correctly typed audit events and the summary's perUser breakdown is keyed by the branded UserId type.
challenge.ts 
// Core types at a glance

export type PermissionAction = "read" | "write" | "delete" | "admin";

export type AccessResult =
  | { outcome: "granted"; role: RoleId }
  | { outcome: "denied";  reason: string };

export type AuditEvent =
  | { kind: "AccessGranted"; userId: UserId; resource: Resource;
      action: PermissionAction; roleId: RoleId; timestamp: number }
  | { kind: "AccessDenied";  userId: UserId; resource: Resource;
      action: PermissionAction; reason: string; timestamp: number }
  | { kind: "RoleInherited"; tenantId: TenantId;
      childRoleId: RoleId; parentRoleId: RoleId; timestamp: number };

// Main entry points
export function resolvePermissions(
  tenant:      Tenant,
  startRoleId: RoleId,
  emitEvent:   (event: AuditEvent) => void,
): ReadonlySet<PermissionAction>;

export function buildAuditTrail(
  tenant:   Tenant,
  requests: ReadonlyArray<AccessRequest>,
): ReadonlyArray<AuditEvent>;

export function summariseAudit(
  events: ReadonlyArray<AuditEvent>,
): AuditSummary;
Hints (click to reveal)

Hints

  • Branded types are plain string intersections — the compiler treats them as distinct even though they're both `string` at runtime; use small factory functions to construct them safely.
  • For `resolvePermissions`, keep a `Set<RoleId>` of visited role IDs and stop traversal when the next parentRoleId is already in the set — this is your cycle guard.
  • When switching over `AuditEvent.kind` in `summariseAudit`, TypeScript will narrow each branch automatically; add a `default` branch with an `assertNever` helper to make the match exhaustive.
