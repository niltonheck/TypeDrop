Typed Event Stream Aggregator with Windowed Rollups

You're building the analytics pipeline for a real-time monitoring dashboard. Raw telemetry events stream in from multiple services, and your job is to validate them, bucket them into fixed time windows, and compute per-metric rollups — with the compiler enforcing every event shape, window boundary, aggregation kind, and output record.

Goals

  • Implement `validateEvent` to narrow `unknown` → `TelemetryEvent` using a `ValidationResult` discriminated union, checking every field at runtime without `any` or type assertions.
  • Implement `assignWindow` and `groupByWindow` to correctly bucket events into fixed-size time windows and index them by a `(windowKey × serviceId × metric)` key path.
  • Implement `aggregate` with an exhaustive dispatch over every `AggregationKind` literal so the compiler forces you to handle all five strategies.
  • Wire everything together in `processEventStream`, using the `MetricAggregationConfig` mapped type to look up the canonical aggregation strategy per metric and return sorted `RollupRecord[]` alongside typed rejected entries.
challenge.ts 
// Key types & main pipeline signature

type MetricName = "cpu_usage" | "memory_usage" | "request_latency" | "error_rate" | "throughput";
type AggregationKind = "sum" | "avg" | "min" | "max" | "count";

type ValidationResult<T> =
  | { readonly ok: true;  readonly data: T }
  | { readonly ok: false; readonly error: string };

interface TelemetryEvent {
  readonly serviceId: string;
  readonly metric: MetricName;
  readonly value: number;
  readonly timestampMs: number;
  readonly aggregation: AggregationKind;
}

type MetricAggregationConfig = { [K in MetricName]: AggregationKind };

interface RollupRecord {
  readonly window: { startMs: number; endMs: number };
  readonly serviceId: string;
  readonly metric: MetricName;
  readonly aggregation: AggregationKind;
  readonly result: number;
  readonly eventCount: number;
}

declare function processEventStream(
  rawEvents: readonly unknown[],
  windowSizeMs: number,
  config: MetricAggregationConfig
): { rollups: RollupRecord[]; rejected: Array<ValidationResult<never>> };

Hints

  • For `validateEvent`, build an array of the valid `MetricName` literals and use `Array.prototype.includes` — but note you'll need to widen the type correctly so the compiler accepts an `unknown` value as the argument.
  • The `WindowedGroups` type uses `Partial<Record<MetricName, TelemetryEvent[]>>` for the innermost level — use the nullish-coalescing assignment operator (`??=`) to lazily initialise each level as you iterate.
  • In `processEventStream`, collect failures as `ValidationResult<never>` — a `ValidationResult<TelemetryEvent>` where `ok === false` is assignable to `ValidationResult<never>` because the `data` field is absent on the false branch.
