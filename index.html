Typed Product Catalog Filter & Grouper

You're building the browse-page logic for an e-commerce storefront. Raw product records arrive from a database query and must be filtered by a typed criteria object, then grouped into a strongly-typed map — the compiler must enforce that every filter key matches a real product field and that the grouped output preserves the correct value types throughout.

Goals

  • Define `StringKeys` as a conditional mapped type that extracts only the string-valued keys of `Product`.
  • Implement `filterProducts` so it returns products matching ALL supplied `FilterCriteria` fields using logical AND.
  • Implement `groupBy` constrained to `StringKeys` so it buckets products by any string-valued product field.
  • Compose both utilities in `filterAndGroup` with a fully inferred return type — no manual annotation.
challenge.ts 
type Category = "electronics" | "clothing" | "books" | "home";

type Product = {
  id: string;
  name: string;
  category: Category;
  priceUsd: number;
  inStock: boolean;
  rating: number;
};

// Keys of Product whose value type extends string (id | name | category)
type StringKeys = { [K in keyof Product]: Product[K] extends string ? K : never }[keyof Product];

// Every field is optional; values must match the Product field type exactly
type FilterCriteria = { [K in keyof Product]?: Product[K] };

Hints

  • For `StringKeys`, use a mapped type with a conditional on `Product[K] extends string ? K : never`, then index with `[keyof Product]` to get the union.
  • In `filterProducts`, `(Object.entries(criteria) as Array<[keyof Product, unknown]>)` can help you iterate criteria pairs — but think about whether you actually need a cast, or if `Object.keys` with a narrowing approach avoids it.
  • In `groupBy`, index into a product with `product[key]` — TypeScript already knows the result is a `string` because `K extends StringKeys`.
