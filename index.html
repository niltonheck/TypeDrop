Typed Streaming Log Aggregator with Plugin Pipeline

You're building the observability backbone for a cloud-native platform. Raw log entries stream in from multiple services, pass through a typed plugin pipeline (enrichment → filtering → transformation), and are aggregated into per-service health summaries — the compiler must enforce plugin input/output contracts, discriminated log levels, and exhaustive aggregation shapes with zero escape hatches.

Goals

  • Define the `LogEntry` discriminated union so each severity level carries its own distinct metadata fields, with the `level` literal acting as the discriminant.
  • Implement `Plugin<In, Out>` and the `PipelineInput` / `PipelineOutput` conditional types so the compiler threads input/output types through the pipeline tuple automatically.
  • Build `buildPipeline` with variadic tuple generics so plugins execute sequentially and type-check end-to-end, and wrap execution in the `Result<T, E>` monad via `runPipelineWithResult`.
  • Implement `aggregateLogs` with a fully exhaustive switch over `LogLevel` (using `assertNever`) that zero-fills all level counts and derives the correct `HealthStatus` and `topErrors`.
challenge.ts 
// Key types & main function signatures

type LogLevel = "debug" | "info" | "warn" | "error" | "fatal";
type ServiceId = string & { readonly __brand: "ServiceId" };

// Discriminated union — each level carries its own metadata shape
type LogEntry =
  | { level: "debug" | "info"; id: string; serviceId: ServiceId; /* … */ }
  | { level: "warn";  warnCode: string;  /* … */ }
  | { level: "error"; errorCode: string; stack: string; /* … */ }
  | { level: "fatal"; errorCode: string; stack: string;
      affectedServiceIds: ServiceId[]; /* … */ };

// Generic plugin interface — In and Out must extend RawLogEntry
interface Plugin<In extends RawLogEntry, Out extends RawLogEntry> {
  name: string;
  process(entries: In[]): Promise<Out[]>;
}

// Builds a type-safe sequential pipeline from a tuple of plugins
function buildPipeline<Stages extends Plugin<RawLogEntry, RawLogEntry>[]>(

): Pipeline<Stages>;

Hints

  • For `PipelineInput`/`PipelineOutput`, reach for `infer` inside a conditional type: `Stages extends [Plugin<infer In, any>, ...] ? In : never` — then adapt to avoid `any` by using `RawLogEntry` as the fallback bound.
  • The variadic `buildPipeline` signature works best when `Stages` is constrained as a non-empty tuple: `[Plugin<RawLogEntry, RawLogEntry>, ...Plugin<RawLogEntry, RawLogEntry>[]]`.
  • Inside `aggregateLogs`, model your per-service accumulator as a mutable object typed exactly as `ServiceSummary` (minus `status`/`topErrors` derived at flush time) — the `LevelCounts` mapped type will force you to initialise all five keys up front.
