Typed Middleware Pipeline Executor with Typed Context & Error Lanes

You're building the request-processing core for an API gateway. Every inbound request passes through a configurable middleware pipeline — authentication, rate-limiting, transformation, and logging — where each middleware can enrich a shared typed context, short-circuit with a typed error, or pass control to the next stage. The compiler must enforce every middleware shape, context mutation, error variant, and exhaustive final outcome with no escape hatches.

Goals

  • Define `MiddlewareResult<TOut>` and `PipelineOutcome<TFinal>` as exhaustive discriminated unions with the correct generic constraints.
  • Implement `runPipeline` to execute middleware sequentially, threading enriched context forward and capturing every halt/respond/throw outcome with the correct variant.
  • Implement `reportOutcome` with a fully exhaustive outer switch over `PipelineOutcome` variants AND an inner exhaustive switch over `PipelineError.kind` for the 'halted' branch.
  • Implement the three middleware factories (`makeAuthMiddleware`, `makeRateLimitMiddleware`, `makeLoggingMiddleware`) with their precise typed signatures and correct halt/next logic.

Hints

  • Start with the discriminated unions (`MiddlewareResult`, `PipelineOutcome`, `PipelineError`) — all implementation depends on getting those shapes right first.
  • For exhaustive switches, add a `never`-asserting default branch: `const _exhaustive: never = x; throw new Error(...)` — the compiler will flag any unhandled variant.
  • The `Middleware<TIn, TOut extends TIn>` constraint means `TOut` must be a superset of `TIn`; when a middleware adds fields, express it as `TIn & { newField: Type }` for `TOut`.
