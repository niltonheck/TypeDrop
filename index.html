Typed Playlist Builder: Track Filtering, Sorting & Duration Rollup

You're building the core logic for a music streaming app. Users create playlists from a typed track catalogue, filter tracks by genre or mood tag, sort them by various criteria, and compute a typed duration summary — with the compiler enforcing every track shape, filter predicate, sort key, and rollup result.

Goals

  • Define `SortKey`, `FilterCriteria`, and `DurationSummary` with precise, strict types — no `any`, no loose `string`.
  • Implement `filterTracks` so that every present criterion is applied as an AND-condition and the original playlist is never mutated.
  • Implement `sortTracks` for all four `SortKey` values in both directions, preserving the original playlist.
  • Implement `computeDurationSummary` including the zero-padded `HH:MM:SS` formatted string and correct `null` handling for empty arrays.

Hints

  • For `SortKey`, think about which `Track` fields are naturally comparable with `<` / `>` — that's your exact union.
  • A single-pass `Array.prototype.reduce` can compute `totalSeconds`, `longestTrack`, and `shortestTrack` all at once.
  • To build `formatted`, integer-divide and modulo your way from total seconds into hours/minutes/seconds, then use `String.prototype.padStart(2, '0')`.
