Typed Recipe Cost Calculator

You're building the pricing engine for a meal-kit delivery app. Recipes are made up of ingredients with quantities and units, and you need to calculate costs, flag expensive recipes, and summarize a weekly menu — with the compiler enforcing every unit, field name, and summary shape.

Goals

  • Implement `toBaseUnit` using a `Record<Unit, number>` multiplier map to convert any quantity to its ingredient's base unit.
  • Implement `calculateRecipeCost` to look up prices, convert units, sum ingredient costs, and populate a fully-typed `RecipeCost` object.
  • Implement `summarizeMenu` to aggregate an array of `RecipeCost` values into a `MenuSummary` — including `Pick`-typed cheapest/most-expensive fields — and throw a `RangeError` on empty input.
  • Implement `filterByMaxCostPerServing` to return a sorted, filtered `readonly RecipeCost[]` within a given per-serving budget.

Hints

  • A `Record<Unit, number>` multiplier (e.g. `{ kg: 1000, l: 1000, g: 1, ml: 1, unit: 1 }`) makes `toBaseUnit` a one-liner — no `if`/`switch` needed.
  • Remember that `Array.find` returns `T | undefined`; use optional chaining (`?.`) or a nullish fallback to avoid a type error when an ingredient isn't in the price list.
  • `Pick<RecipeCost, 'recipeId' | 'recipeName' | 'costPerServing'>` is already the declared type in `MenuSummary` — you only need to return an object with exactly those three keys, which TypeScript will verify structurally.
