Typed HTTP API Client: Paginated Fetch, Response Validation & Retry

You're building the data-fetching core for a dashboard that pulls paginated records from a REST API. Raw responses arrive as `unknown`, must be validated into strongly-typed pages, retried on transient failures with a typed retry policy, and aggregated into a single typed collection — all enforced by the compiler with no escape hatches.

Goals

  • Implement `parseUserPage` to validate an `unknown` API response into a typed `Page<User>`, surfacing per-item validation errors with indexed field names.
  • Implement `fetchPageWithRetry` with linear backoff, retrying only error kinds listed in the policy and wrapping exhausted attempts in a typed `exhausted` error.
  • Implement `fetchAllUsers` to sequentially page through all results, threading the `Result` monad through so any failure short-circuits the entire fetch.
  • Implement `groupUsersByRole` and `summariseUsers` using `Partial<Record<User["role"], …>>` so the compiler omits keys for absent roles.
challenge.ts 

// Core types you'll work with:
export type SortDirection = "asc" | "desc";
export type UserSortField = "name" | "email" | "createdAt";

export interface User {
  id: string; name: string; email: string;
  role: "admin" | "editor" | "viewer";
  createdAt: string;
}
export interface Page<T> {
  data: T[]; page: number; pageSize: number;
  totalPages: number; totalItems: number;
}
export type Result<T, E> = { readonly ok: true; readonly value: T }
                         | { readonly ok: false; readonly error: E };
export type ApiError =
  | { kind: "network";    message: string }
  | { kind: "timeout";    message: string; afterMs: number }
  | { kind: "http";       status: number;  message: string }
  | { kind: "validation"; fields: string[]; raw: unknown }
  | { kind: "exhausted";  attempts: number; lastError: ApiError };

// The four functions you must implement:
export function parseUserPage(raw: unknown): Result<Page<User>, ApiError>;

export async function fetchPageWithRetry(
  url: string, request: PageRequest,
  fetcher: Fetcher, policy: RetryPolicy, delay: Delay
): Promise<Result<Page<User>, ApiError>>;

export async function fetchAllUsers(
  url: string,
  options: { pageSize: number; sort?: PageRequest["sort"];
             fetcher: Fetcher; policy: RetryPolicy; delay: Delay }
): Promise<Result<User[], ApiError>>;

export function groupUsersByRole(users: User[]): Partial<Record<User["role"], User[]>>;
export function summariseUsers(users: User[]): UserSummary;

Hints

  • For `parseUserPage`, call `validatePageEnvelope` first, then map over `data` with `validateUser` — collect all failing indexes into a single `fields` array before returning.
  • In `fetchPageWithRetry`, check `policy.retryOn.includes(error.kind)` to decide between an immediate return and scheduling the next attempt; track the attempt number to compute the delay.
  • For `fetchAllUsers`, a `while (currentPage <= totalPages)` loop that `await`s `fetchPageWithRetry` and returns early on `!result.ok` is the cleanest approach.
