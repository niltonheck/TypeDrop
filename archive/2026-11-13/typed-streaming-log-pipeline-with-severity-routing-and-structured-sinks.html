Typed Streaming Log Pipeline with Severity Routing & Structured Sinks

You're building the observability backbone for a cloud platform. Raw log entries arrive from heterogeneous services, each entry carries a discriminated severity level and a service-specific payload, and your pipeline must parse unknown input, route entries through typed middleware transforms, fan-out to multiple structured sinks (console, file, alerting), and produce a final drain report — all enforced by the compiler with no escape hatches.

Goals

  • Implement `parseLogEntry` to safely narrow `unknown` input into a fully-branded `LogEntry` using type-guard predicates and a `Result<T, E>` return type — no `any` or `as`.
  • Build `severityFilter` and `serviceRedactor` middleware factories, then compose them with `buildPipeline` into a left-to-right short-circuiting chain.
  • Implement `drainPipeline` to parse raw entries, apply the composed pipeline, fan-out surviving entries to all named sinks concurrently via `Promise.allSettled`, and return a typed `DrainReport` with per-sink `SinkOutcome` discrimination.
  • Define `SeverityEntries<S>` using `Extract` and implement `groupBySeverity` so each severity bucket is typed to its specific `LogEntry` variant — using narrowing, not casts.
challenge.ts 

// Core discriminated union — derived from a mapped type
type SeverityLevel = "debug" | "info" | "warn" | "error" | "fatal";

type LogEntry = {
  [S in SeverityLevel]: {
    readonly severity:  S;
    readonly payload:   SeverityPayloadMap[S];
    readonly service:   ServiceName;
    readonly timestamp: Timestamp;
  };
}[SeverityLevel];

// Middleware type
type LogMiddleware = (entry: LogEntry) => LogEntry | null;

// Composed pipeline
function buildPipeline(middlewares: readonly LogMiddleware[]): LogMiddleware { ... }

// Concurrent fan-out to named sinks → typed drain report
async function drainPipeline(
  rawEntries: readonly unknown[],
  pipeline:   LogMiddleware,
  sinks:      Record<string, LogSink>,
): Promise<DrainReport> { ... }

// Conditional type utility
type SeverityEntries<S extends SeverityLevel> = Extract<LogEntry, { severity: S }>;

Hints

  • For `parseLogEntry`, write small helper type-guards (e.g. `function isSeverityLevel(s: unknown): s is SeverityLevel`) with explicit predicate return types — this lets the compiler track narrowing without `as`.
  • In `drainPipeline`, collect each sink's per-entry `Promise<void>` results in a `Record<string, PromiseSettledResult<void>[]>` as you process entries, then compute `SinkOutcome` in a single pass after `Promise.allSettled` resolves.
  • For `groupBySeverity`, iterate entries and use an `if (entry.severity === s)` or a `switch` — the discriminant narrows `entry` to the correct variant automatically, giving you the right element type for each bucket array.
