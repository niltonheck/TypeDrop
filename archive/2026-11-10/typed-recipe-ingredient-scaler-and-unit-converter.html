Typed Recipe Ingredient Scaler & Unit Converter

You're building the recipe engine for a meal-planning app. Recipes list ingredients with typed quantities and units, and your job is to scale them to a target serving count, convert between unit systems (metric ↔ imperial), and produce a normalized shopping list — with the compiler enforcing every unit family, conversion path, ingredient shape, and aggregated result type.

Goals

  • Implement branded-type constructors (`toServingCount`, `toQuantity`) that validate at runtime and narrow at compile time without using `as`.
  • Fill in `UNIT_TO_BASE` using the `satisfies Record<Unit, { baseValue: number }>` pattern so the compiler enforces exhaustiveness across all 11 units.
  • Implement the three overloaded signatures of `convertMeasurement` using `Extract<Measurement, { kind: ... }>` and enforce unit-family safety at both the type and runtime level.
  • Implement `buildShoppingList` to convert all ingredients to canonical base units, aggregate same-name/same-family quantities, handle name collisions across families with a kind suffix, and return entries sorted alphabetically.
challenge.ts 
// Key types & main signatures — preview

type ServingCount = number & { readonly __brand: "ServingCount" };
type Quantity     = number & { readonly __brand: "Quantity" };

type Measurement =
  | { readonly kind: "volume"; readonly quantity: Quantity; readonly unit: VolumeUnit }
  | { readonly kind: "mass";   readonly quantity: Quantity; readonly unit: MassUnit   }
  | { readonly kind: "count";  readonly quantity: Quantity; readonly unit: CountUnit  };

interface Recipe {
  readonly name: string;
  readonly servings: ServingCount;
  readonly ingredients: ReadonlyArray<Ingredient>;
}

// Scale a recipe to a new serving count
function scaleRecipe(recipe: Recipe, targetServings: ServingCount): Recipe;

// Convert a measurement to a different unit in the same family
function convertMeasurement(m: Extract<Measurement, { kind: "volume" }>, targetUnit: VolumeUnit): Extract<Measurement, { kind: "volume" }>;
function convertMeasurement(m: Extract<Measurement, { kind: "mass"   }>, targetUnit: MassUnit  ): Extract<Measurement, { kind: "mass"   }>;
function convertMeasurement(m: Extract<Measurement, { kind: "count"  }>, targetUnit: CountUnit ): Extract<Measurement, { kind: "count"  }>;

// Aggregate scaled recipes into a sorted shopping list
function buildShoppingList(scaledRecipes: ReadonlyArray<Recipe>): ShoppingListEntry[];

Hints

  • Branded types can't use `as` — instead, write a regular type guard (`function isPositiveInt(n: number): n is ServingCount`) and return the value through that guard.
  • For `UNIT_TO_BASE`, start with the `satisfies` keyword: the compiler will immediately tell you which unit keys are missing — use that as your to-do list.
  • In `convertMeasurement`, the overload signatures do the family-safety work; the single implementation signature accepts `Measurement` and `Unit` — use `UNIT_TO_BASE` and the `kind` discriminant to branch correctly.
