Typed Recipe Book: Ingredient Scaling & Shopping List Builder

You're building the core logic for a recipe app. Users save recipes with typed ingredients and serving sizes, scale them up or down for a dinner party, and merge multiple scaled recipes into a single de-duplicated shopping list — with the compiler enforcing every ingredient shape, unit, scaling result, and list entry.

Goals

  • Define the `Unit` string-literal union and wire it through `Ingredient`, `Recipe`, and `ShoppingListEntry` so the compiler rejects any unknown unit string.
  • Implement `scaleRecipe` to return a structurally-identical but quantity-scaled Recipe, throwing a `RangeError` for non-positive serving counts.
  • Implement `mergeShoppingList` to accumulate ingredients across recipes, summing entries that share both name and unit while keeping different-unit entries separate.
  • Implement `formatShoppingList` to emit alphabetically-sorted lines with the correct spacing rule (symbol units like `g`/`ml` attach directly; word units like `tsp`/`whole` use a space) and whole-number display for integer quantities.

Hints

  • A `Map` whose key is a composite string like `"${name}::${unit}"` is the cleanest way to accumulate merged totals without losing the unit distinction.
  • Create a small `Set<Unit>` (or use `includes` on a const array) of the 'symbol-like' units (`g`, `kg`, `ml`, `l`) to decide whether to add a space before the unit in `formatShoppingList`.
  • Use `Number.isInteger(quantity)` (or check `quantity % 1 === 0`) to format whole numbers without a trailing `.00`.
