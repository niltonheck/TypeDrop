Typed API Response Paginator with Result Accumulation

You're building the data-sync layer for a dashboard that ingests records from a paginated REST API. Pages arrive one at a time, each fetch can fail independently, and the final accumulation must be fully typed — distinguishing partial successes from total failures so the UI can render the right state.

Goals

  • Implement the `ok` and `err` constructor functions that produce correctly-tagged discriminated union values.
  • Implement `paginateAll` to sequentially fetch all pages, accumulate items from successes, collect typed errors from failures, and derive the correct `outcome` literal.
  • Implement `filterItems` using a generic type guard to narrow `ReadonlyArray<TItem>` to `ReadonlyArray<TNarrowed>`.
  • Implement `toValidPageNumber` to validate and return a branded `ValidPageNumber` wrapped in a `Result<ValidPageNumber, string>`.
challenge.ts 
// Key types and main function signature

export type Ok<T>  = { readonly status: "ok";  readonly value: T };
export type Err<E> = { readonly status: "err"; readonly error: E };
export type Result<T, E> = Ok<T> | Err<E>;

export interface ApiPage<TItem> {
  readonly page: number;
  readonly totalPages: number;
  readonly items: ReadonlyArray<TItem>;
}

export interface PageFetchError {
  readonly page: number;
  readonly reason: string;
}

export type PageFetcher<TItem> =
  (page: number) => Promise<Result<ApiPage<TItem>, PageFetchError>>;

export interface PaginationSummary<TItem> {
  readonly items: ReadonlyArray<TItem>;
  readonly failures: ReadonlyArray<PageFetchError>;
  readonly totalPagesAttempted: number;
  readonly outcome: "full" | "partial" | "empty";
}

Hints

  • For `paginateAll`, fetch page 1 first and read `totalPages` from the response before looping — the total is unknown until the first successful page arrives.
  • A type guard has the signature `(item: TItem) => item is TNarrowed`; pass it directly to `Array.prototype.filter` and TypeScript will narrow the return type for you.
  • Branded types require a `unique symbol` key in an intersection — you can cast inside `toValidPageNumber` using a type assertion only at the single trust boundary where you've already validated the value.
