Typed Job Queue: Priority Scheduling, Worker Dispatch & Result Aggregation

You're building the scheduling core for a background job processing system. Jobs arrive with typed payloads and priorities, are dispatched to typed worker handlers, and results are aggregated into a structured run report — the compiler must enforce every job variant, worker signature, dispatch outcome, and summary shape.

Goals

  • Define `WorkerFn<J>` and `WorkerRegistry` as a mapped type using `Extract<Job, { kind: K }>` so each job kind maps to a correctly-typed async worker.
  • Implement `sortByPriority` to return a new array sorted highest-priority-first with a stable ordering for equal priorities.
  • Implement `dispatchJob` to narrow the discriminated union by `job.kind` and call the matching worker from the registry — without `any` or unsafe casts.
  • Implement `runQueue` to dispatch all jobs concurrently with `Promise.allSettled`, catch rejecting workers as `JobFailure` entries, and return a fully typed `RunReport`.

Hints

  • For `WorkerRegistry`, the mapped type key `K` gives you the kind string — use `Extract<Job, { kind: K }>` to pull the exact job variant for that key.
  • In `dispatchJob`, a `switch (job.kind)` block narrows `job` to each concrete variant, letting you call `registry[job.kind](job)` inside each case without any type errors.
  • Use `Promise.allSettled` (not `Promise.all`) in `runQueue` so a rejected worker promise doesn't abort the whole batch — then inspect each `PromiseSettledResult` to build the report.
