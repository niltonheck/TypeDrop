Typed Job Queue with Priority Scheduling & Status Tracking

You're building the background job processing core for a SaaS platform. Jobs of different types (email delivery, report generation, data export) are enqueued with a priority level, processed by typed handlers, and their lifecycle — pending → running → succeeded / failed — must be tracked in a strongly-typed status ledger that the compiler fully understands.

Goals

  • Define `Job<K>`, `JobStatus<K>`, `HandlerFn<K>`, and `HandlerRegistry` so the compiler enforces correct payload shapes and lifecycle transitions for every job kind.
  • Implement `enqueue` so the `payload` parameter is automatically narrowed to `JobPayloadMap[K]` at every call site with no manual annotation.
  • Implement `processNext` with priority-then-FIFO scheduling, calling the right handler and updating the ledger — all without any unsafe casts or type assertions.
  • Implement `drain` and `summary` so all jobs are processed sequentially and the final tally covers all four status variants, even those with a count of zero.

Hints

  • A mapped type `{ [K in JobKind]: HandlerFn<K> }` gives each key its own correctly-typed handler — much safer than an index signature.
  • Inside `processNext`, iterating over the specific job kinds (e.g. with an `if`/`else if` or a helper) lets TypeScript narrow `job.kind` so the payload flows into the handler without casting.
  • Use an indexed access type on the discriminated union — `JobStatus<JobKind>["status"]` — to derive the four string literals for the `Record` in `summary()` automatically.
