Typed Book Lending Library: Checkout, Returns & Overdue Tracker

You're building the core logic for a neighbourhood book lending library. Members check out books for a fixed loan period, return them, and the system tracks which loans are overdue — with the compiler enforcing every book shape, loan record, status, and overdue report.

Goals

  • Define the Book, LoanStatus discriminated union, and LoanRecord types with full compiler enforcement and no escape hatches.
  • Implement checkoutBook, returnBook, and markOverdue — returning new records (no mutation) and narrowing the discriminated union correctly.
  • Throw a TypeError in markOverdue when the loan is not in the 'checked-out' state or the due date has not yet passed.
  • Implement getOverdueReport to filter, sort, and aggregate overdue loans into a fully typed OverdueReport.
challenge.ts 
/** ISO-8601 calendar date string brand */
type CalendarDate = string & { readonly __brand: "CalendarDate" };

type Genre = "fiction" | "non-fiction" | "science" | "history" | "biography" | "fantasy";

type Book = { id: string; title: string; author: string; genre: Genre; totalCopies: number };

type LoanStatus =
  | { status: "checked-out"; dueDate: CalendarDate }
  | { status: "returned";   returnedOn: CalendarDate }
  | { status: "overdue";    dueDate: CalendarDate; daysOverdue: number };

type LoanRecord = {
  id: string; bookId: string; memberId: string;
  checkedOutOn: CalendarDate; status: LoanStatus;
};

// Functions you must implement:
declare function checkoutBook(params: {
  id: string; book: Book; memberId: string;
  checkedOutOn: CalendarDate; loanDays: number;
}): LoanRecord;

declare function returnBook(loan: LoanRecord, returnedOn: CalendarDate): LoanRecord;
declare function markOverdue(loan: LoanRecord, today: CalendarDate): LoanRecord;
declare function getOverdueReport(loans: ReadonlyArray<LoanRecord>, today: CalendarDate): OverdueReport;

Hints

  • Use the provided `toCalendarDate` helper and `addDays`/`daysBetween` utilities — you do not need to write your own date arithmetic.
  • Narrow `loan.status.status` with an `if` or `switch` before accessing discriminant-specific fields like `dueDate` or `daysOverdue`.
  • Spread the existing loan record (`{ ...loan, status: newStatus }`) to produce an immutable copy with an updated status.
