Typed Task Scheduler with Priority Queues & Retry Policies

You're building the job-runner core for a background task platform. Tasks arrive with typed payloads, priority levels, and retry policies; your scheduler must enqueue them, drain them in priority order with a concurrency cap, and surface a typed run report — all enforced by the compiler with no escape hatches.

Goals

  • Define all domain types — RetryPolicy, Task<P>, AttemptOutcome, TaskResult, and RunReport — using branded types, numeric literal unions, and discriminated unions.
  • Implement `runWithRetry` that executes a task's handler up to `maxAttempts` times, records every AttemptOutcome, and returns a correctly discriminated TaskResult.
  • Implement `drain` that processes tasks in strict priority-bucket order, runs tasks within each bucket concurrently up to `maxConcurrency`, and clears the queue afterwards.
  • Implement `createScheduler` that wires enqueue and drain together and returns a correctly typed Scheduler object.
challenge.ts 
// Key types and main factory signature

export type TaskId = string & { readonly __brand: "TaskId" };
export type Priority = 1 | 2 | 3;

export type Task<P> = {
  id:          TaskId;
  priority:    Priority;
  payload:     P;
  retryPolicy: RetryPolicy;
  handler:     (payload: P) => Promise<string>;
};

export type AttemptOutcome =
  | { status: "success"; attemptNumber: number; message: string }
  | { status: "failure"; attemptNumber: number; error:   string };

export type TaskResult =
  | { status: "succeeded"; taskId: TaskId; attempts: AttemptOutcome[] }
  | { status: "failed";    taskId: TaskId; attempts: AttemptOutcome[] };

export interface Scheduler {
  enqueue<P>(task: Task<P>): void;
  drain(maxConcurrency: number): Promise<RunReport>;
}

Hints

  • Group enqueued tasks by their `priority` value into a `Map<Priority, Task<unknown>[]>` and iterate the keys in ascending order to enforce bucket sequencing.
  • To batch an array of tasks with a concurrency cap, slice the array into chunks of size `maxConcurrency` and await `Promise.all` on each chunk before moving to the next.
  • Wrap each `handler` call in a try/catch inside a loop; push an AttemptOutcome on every iteration and `break` early as soon as a success is recorded.
