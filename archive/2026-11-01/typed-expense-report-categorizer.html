Typed Expense Report Categorizer

You're building the finance module for a small startup's internal tools. Employees submit raw expense entries, and your job is to validate, categorize, and summarize them — with the compiler enforcing every category label, status field, reimbursement rule, and summary shape.

Goals

  • Implement `validateExpense` to collect ALL validation failures (invalid category, non-positive amount, malformed date) into a typed discriminated-union result.
  • Implement `applycat` to compute the reimbursable amount for a valid expense by capping it against a fully-typed `CategoryCaps` record.
  • Implement `buildEmployeeSummaries` to group valid and invalid expenses by employee, accumulate per-category breakdowns, and return a fully-typed `EmployeeSummary[]`.
  • Use type narrowing on `ValidationResult` (discriminated union) so the compiler enforces which fields are accessible in each branch.
challenge.ts 
/** All valid expense categories */
type ExpenseCategory = "travel" | "meals" | "software" | "hardware" | "training" | "other";

/** Reasons an expense can fail — discriminated union */
type ValidationFailure =
  | { reason: "invalid_category"; raw: string }
  | { reason: "non_positive_amount"; raw: number }
  | { reason: "invalid_date"; raw: string };

/** Discriminated result of validating one RawExpense */
type ValidationResult =
  | { ok: true;  expense: ValidExpense }
  | { ok: false; id: string; failures: ValidationFailure[] };

/** Caps must cover every ExpenseCategory — no omissions allowed */
type CategoryCaps = Record<ExpenseCategory, number>;

function validateExpense(raw: RawExpense): ValidationResult { ... }
function applycat(expense: ValidExpense, caps: CategoryCaps): number { ... }
function buildEmployeeSummaries(raws: RawExpense[]): EmployeeSummary[] { ... }

Hints

  • Use `Array.prototype.includes` with a typed constant array (e.g. `const CATEGORIES = [...] as const`) to narrow a `string` into `ExpenseCategory` without a type assertion.
  • A `Partial<Record<ExpenseCategory, CategorySummary>>` lets you build the `byCategory` map incrementally — use the nullish coalescing assignment operator (`??=`) to initialise missing entries.
  • When narrowing `ValidationResult`, check `result.ok` first — the compiler will then know exactly which branch's fields are available.
