Typed Job Queue with Priority Scheduling & Result Collection

You're building the task-scheduling core for a background job processor. Jobs arrive with different priorities and payload shapes, a concurrency-limited runner executes them, and every result — success or failure — is collected into a strongly-typed summary the compiler fully understands.

Goals

  • Define a three-variant discriminated union `Job` and the generic `JobSuccess`, `JobFailure`, and `JobResult` types with correct constraints.
  • Build a `HandlerRegistry` mapped type that maps each job `kind` to a handler typed for exactly that variant — no broader union.
  • Implement `runQueue` to sort by priority, enforce a concurrency limit, capture every result (success or failure), and return a fully-typed `QueueSummary`.
  • Implement `getSuccesses` so callers automatically receive the narrowed `JobSuccess<JobByKind<K>>[]` type without any explicit annotation at the call site.

Hints

  • For `HandlerRegistry`, a mapped type `{ [K in Job["kind"]]: JobHandler<JobByKind<K>> }` gives each key its own narrowly-typed handler — no union bleed-through.
  • To enforce concurrency, keep a count of active slots and use a queue of pending promises; resolve the next job as each slot frees up.
  • In `getSuccesses`, filter first by `result.job.kind === kind`, then by `result.status === "success"` — two type guards in sequence let TypeScript narrow all the way to `JobSuccess<JobByKind<K>>`.
