Typed State Machine Engine

You're building the workflow engine for an e-commerce order management system. Each order moves through a strict lifecycle — from placement to fulfillment — and the compiler must enforce that only valid transitions are allowed, that transition guards have access to the right context shape, and that side-effect actions are fully typed per transition.

Goals

  • Define the `guard` and `action` properties on the `Transition` interface with correct generic signatures.
  • Define `MachineSnapshot<S>` (with a `can()` method) and the `TransitionResult` discriminated union.
  • Implement `StateMachine` — constructor, `snapshot()`, `send()`, and `patchContext()` — enforcing guard checks and running actions.
  • Implement `createOrderMachine` with all ten pre-configured transitions, guards, and actions wired up correctly.

Hints

  • For `MachineSnapshot`, the `can()` method must both match the transition's `from` state AND evaluate its `guard` — a missing guard means the event is allowed.
  • The `TransitionResult` discriminated union works best with a literal `ok` field — TypeScript will narrow it for you in if/else branches.
  • In `createOrderMachine`, the `action` for PAYMENT_SUCCESS/PAYMENT_FAILED should mutate the context object in place (since `patchContext` is also available on the machine, you may call it from the action via a closure).
