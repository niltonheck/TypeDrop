Typed Expense Report: Categorisation, Budgets & Summary Rollup

You're building the expense-management core for a finance tool. Raw expense submissions arrive as `unknown` JSON, must be validated into strongly-typed records, checked against per-category budgets, and rolled up into a typed summary report — with the compiler enforcing every shape, status flag, and aggregation result.

Goals

  • Define a generic `Result<T>` discriminated union and a `ParseError` discriminated union covering missing_field, invalid_type, and invalid_value variants.
  • Implement `parseExpense` to validate an `unknown` value into a typed `Expense`, returning the first `ParseError` encountered.
  • Define a `BudgetStatus` discriminated union with variant-specific fields (remainingCents / overageCents) and implement `evaluateBudget` to produce the correct variant.
  • Implement `buildSummary` to parse all raw entries, evaluate budgets for every encountered category, and return a fully-typed `ExpenseSummary` rollup.
challenge.ts 

export type ExpenseCategory =
  | "travel" | "meals" | "accommodation"
  | "equipment" | "software" | "other";

export interface Expense {
  id: string;
  submittedBy: string;
  category: ExpenseCategory;
  amountCents: number;   // cents, must be > 0
  date: string;          // "YYYY-MM-DD"
  description: string;
}

export interface Budget {
  category: ExpenseCategory;
  limitCents: number;
}

// Result / ParseError / BudgetStatus / ExpenseSummary — you define these!

export function parseExpense(raw: unknown): Result<Expense>;

export function evaluateBudget(
  expenses: readonly Expense[],
  budget: Budget
): BudgetStatus;

export function buildSummary(
  rawEntries: readonly unknown[],
  budgets?: readonly Budget[]
): ExpenseSummary;

Hints

  • Model BudgetStatus as a discriminated union where the discriminant is a `status` string literal — each variant can then carry its own unique fields without optional properties.
  • In `parseExpense`, check `typeof raw === 'object' && raw !== null` first, then use `'id' in raw` style guards before narrowing each field — this avoids any `as` casts.
  • For the `formatBudgetStatus` exhaustiveness check, add a final `default` branch that passes the status to a helper typed as `(_: never) => never` — the compiler will error if you forget a variant.
