Typed Event Sourcing Engine with Projection & Snapshot

You're building the core of an event-sourced order management system. Domain events are appended to an immutable ledger, typed projections fold them into read models, and periodic snapshots checkpoint state so replays don't have to start from the beginning of time.

Goals

  • Define a five-variant discriminated union `OrderEvent` with branded ID types and implement the three branded constructor functions.
  • Implement `EventStore` with strict sequential version enforcement, `OrderProjector` with exhaustive event folding (all five variants), and `SnapshotStore<S>` with save/load/shouldSnapshot.
  • Wire everything together in `OrderAggregate` so that appending events auto-snapshots at the configured interval and `getReadModel` correctly replays from the nearest snapshot.
  • Implement the constrained generic helper `buildEventStream<E>` that filters by version and returns events sorted ascending.
challenge.ts 
export type OrderEvent =
  | ({ type: "OrderPlaced";   orderId: string; customerId: string; placedAt: Date; totalCents: number } & Base)
  | ({ type: "ItemAdded";     orderId: string; sku: string; qty: number; unitCents: number }           & Base)
  | ({ type: "ItemRemoved";   orderId: string; sku: string; qty: number }                              & Base)
  | ({ type: "OrderShipped";  orderId: string; carrier: string; trackingCode: string; shippedAt: Date } & Base)
  | ({ type: "OrderCancelled";orderId: string; reason: string; cancelledAt: Date }                     & Base);

type Base = { eventId: string; version: number };

export type OrderStatus = "pending" | "active" | "shipped" | "cancelled";

export type OrderReadModel = {
  readonly orderId: string;
  readonly customerId: string;
  readonly status: OrderStatus;
  readonly totalCents: number;
  readonly items: readonly LineItem[];
  readonly shippedAt: Date | null;
  readonly cancelledAt: Date | null;
  readonly lastVersion: number;
};

export interface Projector<S> {
  init(orderId: string): S;
  apply(state: S, event: OrderEvent): S;   // must be exhaustive!
  replayFrom(stream: readonly OrderEvent[], snapshot?: S): S;
}

Hints

  • For exhaustive switch coverage in `OrderProjector.apply`, add a `default: return assertNever(event)` branch — the compiler will catch any missing case.
  • Branded types use `unique symbol` as a phantom property; the constructor just returns the raw string with a type cast — but the cast must live only in the constructor, nowhere else.
  • In `OrderAggregate.getReadModel`, load the snapshot first, then call `buildEventStream` with `snapshot.atVersion` as `fromVersion` to get only the delta events before replaying.
