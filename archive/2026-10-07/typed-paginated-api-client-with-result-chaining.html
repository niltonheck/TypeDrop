Typed Paginated API Client with Result Chaining

You're building the data-fetching layer for an analytics dashboard that consumes a paginated REST API. The client must handle multi-page traversal, surface typed errors without throwing, and aggregate all pages into a single typed collection — all enforced at compile time with no unsafe casts.

Goals

  • Define the `Result<T, E>` discriminated union and its `ok` / `err` convenience constructors with correct generic types.
  • Implement `mapResult` and `flatMapResult` using type narrowing on the `success` discriminant — no type assertions allowed.
  • Implement `fetchPage` to wrap `simulateFetch`, catching network rejections and adapter parse failures into typed `ApiError` results.
  • Implement `fetchAllPages` to cursor-walk all pages sequentially, short-circuiting on the first `Err` and collecting all items on success.

Hints

  • Narrow `Result<T, E>` by checking `result.success === true` — TypeScript will then know the variant and give you `.value` or `.error` without casting.
  • For `fetchPage`, use two nested try/catch blocks (or one with careful branching): one for the network call and one for the adapter — each maps to a different `ApiErrorCode`.
  • In `fetchAllPages`, initialize `cursor` as `string | null = null` and loop while the last page's `nextCursor` is not null — the loop body must be sequential (`await` inside the loop), not parallel.
