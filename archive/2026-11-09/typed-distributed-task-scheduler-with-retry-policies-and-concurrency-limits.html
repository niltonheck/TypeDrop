Typed Distributed Task Scheduler with Retry Policies & Concurrency Limits

You're building the job-execution engine for a distributed background worker system. Tasks arrive with heterogeneous payloads, each task type carries its own retry policy (fixed delay, exponential backoff, or no retry), execution must respect a global concurrency cap, and the final run report must distinguish succeeded, exhausted, and cancelled outcomes — all enforced by the compiler with no escape hatches.

Goals

  • Define all discriminated unions (RetryPolicy, Task<TPayload>, TaskOutcome<TPayload>) with no optional fields and no `any`.
  • Implement `computeNextDelay` with exhaustive narrowing over all three RetryPolicy variants, returning the correct delay or `null` when retries are exhausted.
  • Implement `runScheduler` respecting the concurrencyLimit slot pool, per-task retry loops with computed delays, and global wall-clock cancellation.
  • Implement `partitionOutcomes` returning three arrays each narrowed to the correct TaskOutcome variant via intersection types.
challenge.ts 
// Core types and main function signature preview

type RetryPolicy =
  | { kind: "none" }
  | { kind: "fixed";       delayMs: number; maxAttempts: number }
  | { kind: "exponential"; baseDelayMs: number; maxAttempts: number; factor: number };

type Task<TPayload> =
  | { type: "http";    id: string; payload: HttpPayload;    retryPolicy: RetryPolicy }
  | { type: "compute"; id: string; payload: ComputePayload; retryPolicy: RetryPolicy }
  | { type: "notify";  id: string; payload: NotifyPayload;  retryPolicy: RetryPolicy };

type TaskOutcome<TPayload> =

Hints

  • For the concurrency pool, keep a counter of active slots and use a queue of pending Promises — `Promise.race` over a set of running tasks is one clean approach.
  • For `computeNextDelay`, a `switch` on `policy.kind` gives you exhaustive narrowing; the exponential formula is `baseDelayMs * factor ** (attempt - 1)` and should return `null` when `attempt >= maxAttempts`.
  • For `partitionOutcomes`, filter with a type predicate `(o): o is TaskOutcome<TPayload> & { status: 'succeeded' } => o.status === 'succeeded'` to get compiler-narrowed arrays without assertions.
