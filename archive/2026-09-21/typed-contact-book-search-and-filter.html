Typed Contact Book Search & Filter

You're building the search and filter core for a personal contact management app. Users can look up contacts by name or tag, and the results must be narrowed into strongly-typed shapes the compiler fully understands.

Goals

  • Define a `SearchQuery` type with four optional filter fields, using only the allowed keys.
  • Implement `searchContacts` that applies every provided filter and returns matching contacts without mutating the input.
  • Implement `getContactById` returning `Contact | null` using the branded `ContactId` type.
  • Implement `groupContacts` returning a `Record<ContactGroup, Contact[]>` with every group key present, and implement the generic `pickContactFields` so its return type is inferred precisely as `Pick<Contact, K>[]`.

Hints

  • For `SearchQuery`, model it as an interface or plain object type with all fields marked `?` — no union needed.
  • For the branded `ContactId`, the only safe cast lives in `toContactId`; everywhere else the compiler enforces the brand automatically.
  • For `pickContactFields`, use `Object.fromEntries` + `keys.map` and let the generic `K extends keyof Contact` drive the `Pick<Contact, K>[]` return type — no explicit cast required inside the function body.
