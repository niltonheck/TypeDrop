Typed Permission Policy Engine with Conditional Grants

You're building the authorization core for a multi-tenant SaaS platform. Every API request carries a principal (user or service account) whose access is governed by a layered policy system — role-based defaults, resource-scoped overrides, and runtime conditions — and the compiler must enforce every policy shape, decision outcome, and exhaustive condition evaluation with no escape hatches.

Goals

  • Implement roleAtLeast to establish a strict total ordering over the Role union without any casting.
  • Implement evaluateCondition to exhaustively handle all 7 Condition variants, including recursive 'all' and 'any' compositions.
  • Implement evaluatePolicy and evaluatePolicies to enforce priority rules: tenant isolation → explicit deny → role/resource policies → abstain.
  • Implement batchEvaluate with Promise.all and buildAuditSummary with a fully-keyed mapped ActionSummary type.
challenge.ts 

// Key types and main engine function:

type Action = "resource:read" | "resource:write" | "resource:delete"
            | "resource:share" | "admin:impersonate" | "admin:audit";

type Role = "viewer" | "editor" | "manager" | "admin" | "superadmin";

type Decision =
  | { outcome: "allow";   grantedBy: PolicyId }
  | { outcome: "deny";    reason: DenyReason  }
  | { outcome: "abstain" };

type Condition =
  | { kind: "time-window";  startHour: number; endHour: number }
  | { kind: "ip-allowlist"; cidrs: string[]                    }
  | { kind: "mfa-required"                                     }
  | { kind: "same-tenant";  resourceTenantId: TenantId         }
  | { kind: "min-role";     role: Role                         }
  | { kind: "all";          conditions: Condition[]            }  // recursive AND
  | { kind: "any";          conditions: Condition[]            }; // recursive OR

type ActionSummary = {
  readonly [A in Action]: {
    readonly allowed: number; readonly denied: number; readonly abstained: number;
  };
};

Hints

  • A const array of roles in ascending order (e.g. `const ROLE_ORDER = ['viewer', 'editor', ...] as const`) lets you compare indexes without any casting — but you'll need to type it so indexOf is safe.
  • For exhaustiveness in a switch/if-else chain over a discriminated union, call assertNever(x) in the default branch — the compiler will error if any variant is unhandled.
  • ActionSummary's mapped type means you must initialise every Action key before returning — consider building a zero-filled record first using a typed array of all Action values.
