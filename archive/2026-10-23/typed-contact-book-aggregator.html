Typed Contact Book Aggregator

You're building the data layer for a personal contact book app. Contacts arrive from multiple sources (manual entry, email import, phone sync), and you need to group, search, and summarize them — with the compiler enforcing every field name, group key, and summary shape.

Goals

  • Define `ContactSortField` using a mapped + conditional type that extracts only the `string | Date` keys of `Contact`, excluding nullable fields.
  • Define `ContactSummary` with utility types (`Omit`/`Pick`) — never manually re-list property names — and add a `displayName` field via intersection.
  • Implement `groupBySource` so that every `ContactSource` key is always present in the result, even when its contact list is empty.
  • Implement `searchContacts` with a non-empty tuple parameter type so the compiler rejects an empty `fields` array at the call site.

Hints

  • For `ContactSortField`, use a distributive mapped type: map each key to itself or `never`, then index with `[keyof Contact]` to collect the keepers.
  • For `ContactSummary`, `Omit<Contact, 'tags' | 'phone'> & { displayName: string }` is the idiomatic two-step — no manual property listing needed.
  • To guarantee all `ContactSource` keys exist in `groupBySource`, seed your accumulator with `{ manual: [], email: [], phone: [] }` before iterating.
